# M2 benchmarks: lineage on the real snapshot

**Machine:** the same container as M0/M1: 4 vCPU Xeon @ 2.1 GHz, native
release build, single-threaded. **Data:** NYC 311 snapshot `3b42e46a…`
(7,111,809 rows).
**Harness:** `cargo run --release -p receipts-bench --bin m2 -- <snapshot dir>`.
Peak RSS for the whole run was 946 MB.

**Plan:** noise complaints (two types, closed on or after created), then
hours to close, grouped by borough (count, median), sorted by median.

## Capture cost

| | M1 (no lineage) | M2 (with lineage) |
|---|---|---|
| `execute`, median of 5 | 585 ms | 622 ms (+6%, within run-to-run noise) |
| Lineage held | — | 9.4 MB |

Per step: the scan, the map and the final 6-row sort cost nothing or almost
nothing. The filter's selection vector (1,178,593 rows) and the
aggregate's group membership each take 4.7 MB.

## Checked against the data

For every borough:
- The number of source rows traced equals that row's `requests` count.
- Every traced source row has that borough, is one of the two noise
  complaint types, and has `closed_date >= created_date`.
- The forward trace of a Bronx source row reaches exactly the Bronx output
  row.
